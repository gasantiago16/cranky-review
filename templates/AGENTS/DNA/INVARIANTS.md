# Invariants

What must stay true at runtime, and the failure that taught it.

**Admission test:** could you write a test that fails when this stops being true? If yes, it belongs here. A choice among alternatives goes in DECISIONS. Where code lives goes in ARCHITECTURE. Anything a customer can observe goes in PRODUCT.

One entry per invariant. The heading states the rule so it can be violated. Under it: the mechanism that enforces it, and the incident that made it necessary.

Invariants are **earned**, not invented. Seed from bugs you already paid for before using cranky as a merge gate on feature work.
